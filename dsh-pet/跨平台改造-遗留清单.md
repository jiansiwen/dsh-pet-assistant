# dsh-pet 跨平台改造 · 仍无法兼容清单

> 本次改造把能跨平台的部分都跨了。这份清单列的是**改不了的部分**，以及**为什么改不了**。
> 每条都给了替代方案 —— 没有一条是"功能消失且没得用"。

## 一、系统层面没有对应实现（不是没做，是做不了）

### 1. 语音唤醒「小潘」

- **Windows 的做法**：`System.Speech` 的离线识别器 + 自定义 grammar，纯本地零依赖。
- **为什么 macOS 不行**：macOS 没有等价的系统级离线识别 API。
  要自己做就得常驻跑一个流式模型（约 458MB 常占内存）或引第三方语音框架 ——
  这不是"改一处命令拼法"的量级，且常驻监听的功耗与隐私代价需要单独设计。
- **替代**：全局快捷键 `Cmd+Option+P`；或直接点角色。
- **代码位置**：`src/main/platform.ts` 的 `supportsWakeWord`

### 2. 「点面板外面自动收起」

- **Windows 的做法**：`assets/pointer-watch.ps1` 装全局鼠标钩子。
- **为什么 macOS 不行**：全局鼠标钩子需要**辅助功能（Accessibility）授权**，
  而一个 PowerShell 脚本拿不到这个授权（需要 .app 打包 + 用户手动在系统设置里勾选）。
  注意：**穿透本身是好的** —— 判定完全在渲染层，不走这个钩子。
  缺的只是"点面板外面把它收起来"这一个便利动作。
- **替代**：按 `Esc`；或点角色本身。
- **代码位置**：`platform.ts` 的 `supportsGlobalPointerWatch`；
  调用方 `index.ts` 的 `setPointerWatch` 会**静默降级**（不弹错误提示）

### 3. 前台活动记录（插件侧）

- **Windows 的做法**：`assets/sampler.ps1` 调 Win32 的 `GetForegroundWindow` + `GetWindowText`。
- **为什么 macOS 不行**：同一套 API 不存在。macOS 上取前台应用需要
  `NSWorkspace`（要写原生模块）或 AppleScript（要 Automation 授权 + 逐个应用弹窗确认）。
  两者都要重新设计授权模型 —— 而这个功能采集的是**隐私数据**，授权模型不能顺手凑。
- **替代**：该功能在 macOS 上会如实报"没有在记录活动"（不是静默失败）。
- **代码位置**：`dsh-personal-assistant/src/index.ts` 的 `captureBlockedReason`

## 二、未实现但**可以**补（本次没做，因为超出"兼容"的范围）

### 4. Linux 上的音频播放 / 合成回退

- **现状**：`playAudioSpec` / `speakOfflineSpec` 在 Linux 上返回 `null`，朗读会如实报"没实现"。
- **为什么没顺手做**：Linux 没有统一的系统命令。可用的候选各有依赖：
  `aplay`（alsa-utils，只吃 wav）、`paplay`（PulseAudio）、`ffplay`（要 ffmpeg）、
  `mpv` / `spd-say`（要装包）。**挑任何一个都是引入外部依赖**，而选错会让用户看到
  "没声音"却不知道缺哪个包。这该是一次单独的设计决定，不是跨平台改造的副产品。
- **建议做法**：按可用性探测（`which` 依次尝试），全都没有就保持现状报错。
- **代码位置**：`platform.ts` 的 `playAudioSpec` / `speakOfflineSpec`

### 5. macOS / Linux 上的录音回退（`asr-record-fallback`）

- **现状**：`recordAudioSpec` 在这两个平台上返回 `null`。
- **影响范围很小**：这只在**渲染层 Web Audio 也拿不到麦克风**时才走到。
  主路径（`getUserMedia`）在 macOS 上是通的，所以正常情况不受影响。
- **代码位置**：`platform.ts` 的 `recordAudioSpec`

## 三、刻意保留的平台差异（不是缺陷）

### 6. Windows 上宠物不跟随切换虚拟桌面

- `setVisibleOnAllWorkspaces` 在 Windows 上是**空操作**（Electron 官方文档明说）。
- 所以 Windows 上切桌面时宠物不跟着走、全屏应用会盖住它。
- **这是系统限制，不是代码问题** —— macOS/Linux 上这个能力是真生效的。

### 7. 会议密钥不能跨平台迁移

- Windows 的 `key.bin` 由 DPAPI 包装，macOS 由 Keychain 包装，**互相解不开**。
- **这是刻意的**：密钥就该绑在机器上。否则拿到 `userData` 目录的人就能解开全部录音。
- 代价：把 Windows 的 `userData` 整个拷到 Mac，旧会议录音读不出来（会明确报 `lost`，
  不会静默重建密钥覆盖掉）。
- **代码位置**：`src/main/dpapi.ts`

### 8. 托盘交互方式不同

- Windows/Linux：**单击**托盘图标切换角色显示。
- macOS：设了右键菜单后系统不再派发 click 事件，所以走**右键菜单里的「隐藏/显示角色」**。
- 功能不缺，只是"最快的那一下"在 macOS 上点不出来。

### 9. Windows 旧识别引擎兜底只在 Windows 上

- 没装本地模型时，Windows 还能退回系统自带的 `System.Speech`（准确率有限）。
- macOS/Linux 没装模型就直接报"模型没装" —— 因为那边确实没有可退的东西。
- **代码位置**：`asr.ts` 的 `legacyEngineAvailable`

## 四、使用注意（不是兼容性问题，但会踩）

### 10. macOS 上**必须**重新 `pnpm install`

不要把 Windows 的 `node_modules` 拷过去。里面有
`sherpa-onnx-win-x64`、`koffi-win32-x64`、`@napi-rs/canvas-win32-x64-msvc`、
`@img/sharp-win32-x64`、`node-addon-require-builtin-win32-x64-msvc`
等一批 **win32 原生二进制**，在 macOS 上加载会失败。

顺带说明：`sherpa-onnx-*` 已移到 `optionalDependencies`，
pnpm 会按当前平台自动只装匹配的那个（实测验证过），所以 `pnpm install` 不会因为平台字段报错。

### 11. 打包成 `.app` 才需要 Info.plist 权限声明

- 开发态 `pnpm start`：跑的是 Electron 自己的 Info.plist（已声明麦克风用途）→ 能说话。
- 打包后：**必须**用 `build/electron-builder.yml`（已备好 `NSMicrophoneUsageDescription`
  + `entitlements.mac.plist`），否则调 `getUserMedia` 时系统会**直接终止进程**。
- 命令：`pnpm run pack:mac`

### 12. macOS 首次使用麦克风会弹一次授权框

- 装配时会主动请求（`systemPreferences.askForMediaAccess`），把授权提前到用户按说话键之前。
- 拒绝之后系统不会再弹第二次，需要去「系统设置 → 隐私与安全性 → 麦克风」手动打开。

## 附：本次改造的关键设计决定

1. **平台差异全部收在 `src/main/platform.ts` 一处**。
   以前 `'powershell'` 这个字符串散在七个文件里，加一个平台要满地找。
   现在只有这里知道"Windows 的音频播放器是 PowerShell 脚本"。
   拼法是**纯函数**，所以能在 Windows 上一台机器跑遍三种系统的测试（`tests/platform.test.ts`）。

2. **传 `CommandSpec`（命令名 + 参数数组）而不是拼字符串**。
   拼字符串要处理引号与转义，而朗读文本里什么都可能有（中文、空格、引号、换行）。
   传数组给 `spawn` 时操作系统直接收 argv，没有 shell 参与，注入面为零。

3. **识别改成进程内解码**，这是让 macOS 能用的**关键一步**。
   旧实现 spawn `sherpa-onnx-offline.exe` —— 模型本身是跨平台的，却被一个文件名挡死。
   换成 Node API 后同一个模型目录三个系统都能用，还顺带少了进程启动开销。

4. **"能力不存在"与"运行失败"分开处理**。
   前者是确定的、无法修的 → 静默降级或直接改状态（不弹错误、不每三秒重试）；
   后者是可能修的 → 如实报错并给恢复入口。
   混在一起的后果：macOS 用户每次开面板都看到一句"鼠标监听仅支持 Windows"。
